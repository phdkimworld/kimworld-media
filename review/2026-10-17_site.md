공통 제약: 매수·매도 권유 문구 없음, 숨긴 답은 3부에만(메타·FAQ·OG·이미지에 넣지 않음), 공개된 slug는 바꾸지 않음. 템플릿·build.py 변경은 지난 페이지의 `<head>`에도 적용된다. '지난 발행물 수정 금지'(G장)는 원고 내용에 대한 규칙이므로, 화면·메타 생성 코드 변경은 운영자에게 한 번 확인받는다.

### P1. 메타 설명을 1~2문장·110자 안팎으로 하고 RSS에 본문 전체 넣기 [바로] — S1 +0.5, 네이버 수집
- 근거: N2(1~2문장), G3(고유·정확한 설명), N4(RSS에 본문 전체). 지금은 202~296자에 질문으로 끝나고, '주가'라는 단어가 빠져 있다. RSS `<description>`은 summary뿐이다.
- 바꿀 곳:
  - `build.py seo_fields()`: `search_desc`를 새로 만든다. `"<이름>(<티커>) 주가: " + summary 첫 1~2문장(110자 안팎, 숫자 대비)`. 끝에 '짧은 답'의 첫 문장 요지를 한 줄 붙일 수 있다(숨긴 답 숫자는 쓰지 않음). 코인은 '코인 시세:'.
  - `templates/report.html {% block description %}` → `r.search_desc`.
  - `build.py` RSS(1127행 근처): `xmlns:content`를 넣고 `<content:encoded>`에 본문 HTML 전체(광고·스크립트 제외).
  - SKILL.md **R1.2 summary 규칙 고침**: "첫 문장 = 이름(티커)+주가(코인은 가격·시세)+대비 숫자 두 개, 전체 2문장·120자 이내 권장. 질문은 둘째 문장 끝에만." 지금의 "제목이 연 질문에 답하지 않는다"는 G6 '이해에 필요한 정보 숨기기'와 부딪힌다. 그래서 "근본 동인은 한 구절로 밝히고, 조건·횟수(숨긴 답)만 미룬다"로 바꾼다.
- 기대 효과: Google·네이버가 메타 설명을 그대로 쓸 확률이 오르고, 검색 결과 첫 줄에 검색어(이름·주가)가 굵게 보인다. 네이버 수집·색인이 빨라진다.
- 다음 지표: Search Console 리포트 페이지 CTR(검색어 '<이름> 주가'), 서치어드바이저 수집 문서 수와 노출, GA4 google/organic·naver/organic 세션.

### P2. Discover·네이버용 대표 이미지를 글자 적은 차트형으로 따로 만들고 JSON-LD에 세 비율 넣기 [바로 + OG 문구는 A/B] — S6 +1.0, S2 +0.5
- 근거: G6(1200px 이상·16x9·글자 많은 이미지 지양), G4(16x9·4x3·1x1 배열), N3(홍보 배너성 이미지 제외 가능). 지금 대표 이미지는 글자 많은 1200x630 한 장과 'CTA 버튼'이고, 본문 차트는 1080px다.
- 바꿀 곳:
  - `build.py make_og()` 옆에 `make_hero()`를 만든다. 대표 차트를 크게 쓰고 글자는 '회사명(티커)'와 숫자 하나만 넣는다. 버튼·도메인 문구는 넣지 않는다. 크기는 `og/<slug>-16x9.png`(1280x720), `-4x3.png`(1200x900), `-1x1.png`(1200x1200).
  - `templates/report.html` Article `"image"` → 세 장 배열. `sitemap.xml` image에도 16x9를 넣는다.
  - 차트 생성(R5, `report_figures.py`·`chart_dark.py`) 출력 가로를 1080 → 1200 이상으로 바꾼다.
  - og:image(카카오톡용)는 두 안을 **A/B(E9)**로 비교한다. A = 지금 카드, B = '무료 리포트 전문 보기' 버튼을 빼고 훅 2줄+차트를 키운 2:1(1200x600) 카드. 카카오 데브톡의 2:1 권장(비공식)을 반영한 것이다.
- 기대 효과: Discover 노출 자격(큰 이미지)을 갖추고, 네이버 검색 썸네일에 쓰일 수 있게 된다. 지금은 Discover 유입이 사실상 막혀 있다.
- 다음 지표: Search Console 'Discover' 보고서 노출·클릭(지금 0으로 추정), 네이버 썸네일 표시 여부. E9는 Threads·카카오 공유 링크(utm_content별) 1,000노출당 방문.

### P3. 코인 리포트의 검색어·스키마를 코인에 맞추기 [바로] — RENDER·NEAR S1 +1.0, S2 +1.0
- 근거: G2(실제 내용과 맞는 제목), N1(주제를 명확히). 업비트·한국 검색 표기는 '렌더토큰', '니어프로토콜', '~ 코인'이다. JSON-LD `Corporation+tickerSymbol`은 자산 유형이 틀렸고, '코인·블록체인 관련주'는 주식 용어다.
- 바꿀 곳:
  - `build.py seo_fields()`: 테마가 코인이면 `seo_title = "<이름>(<티커>) 코인 시세 분석 — <훅>"`, keywords는 `"<이름> 코인", "<티커> 코인 전망", "<업비트 표기> 시세"`.
  - `data/tickers.yaml`에 업비트 한글 표기(렌더토큰·니어프로토콜)를 별칭으로 추가한다.
  - `templates/report.html` about: 코인이면 `{"@type":"Thing", "name", "alternateName"}`로 하고 tickerSymbol은 뺀다. Breadcrumb 2단계는 코인 테마일 때 '관련주' 꼬리를 뺀다.
  - SKILL.md R1.2 코인 제목 틀 `"<이름> 코인, <대비 질문> | 가격 내러티브와 패턴 투자전략"`(G1 영상 제목 '가격 미스터리'와 짝).
- 기대 효과: 코인 회차가 '○○ 코인' 검색어에 맞게 잡히고, 구조화 데이터 오류 소지가 사라진다.
- 다음 지표: Search Console 검색어 '렌더 코인', '니어 코인' 노출·순위, 코인 리포트 organic 세션.

### P4. '함께 읽기'를 실제로 닿는 자리로 옮기고 카드로 바꾸기 [A/B] — S5 +1.0
- 근거: 7일 mid_next_click 0, 유튜브 세션당 1.42쪽, 스크롤 30~57%. 지금 링크는 글자 22~27% 지점의 한 줄 글자이고 제목에 시리즈 꼬리가 붙어 길다. RENDER는 링크가 없다. G7(주 콘텐츠와 구분되는 탐색)과 Discover의 '세션 연장'은 간접 신호다.
- 바꿀 곳:
  - `build.py insert_mid_next()`: 링크 문구를 `share_title`(꼬리 없는 이름+훅)로 바꾸고 대표 차트 썸네일(`chart_meta`)을 붙인 카드로 만든다. 자리를 못 찾으면 2부 끝 앞에 강제로 넣는다(RENDER 보정).
  - **E10 A/B**: A = 지금 40% 문단 사이, B = '짧은 답' 바로 뒤와 2부 마지막 시기 '다음 ·' 예고 줄 옆, 두 곳. 고를 때는 같은 테마보다 **같은 패턴(예: MBOT↔GOSS 증자 구조)**과 유튜브 영상이 있는 리포트를 먼저 고른다(`related` 정렬 기준 추가).
  - 맨 아래 `다음에 읽을 만한`은 그대로 둔다.
- 기대 효과: 세션당 쪽수 +0.1~0.2, 여러 쪽 본 세션 20% → 25% 안팎.
- 다음 지표: mid_next_click ÷ 리포트 페이지뷰(조별), 유튜브 유입 세션당 쪽수, multi_page_pct.
