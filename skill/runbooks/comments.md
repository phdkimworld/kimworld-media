# 댓글 처리 지침 (매시간 예약 작업에서 `tools/hourly.py`가 ACTION을 냈을 때만 읽는다)

2026-11-10 토큰 절약 개편: 예약 작업은 먼저 `python3 tools/hourly.py`를 돌린다. 이 스크립트가 유튜브·사이트·SNS 목록 읽기, 짧은 감사·인사와 이모지 답글(틀 문장), 사이트 요청 확인, 3시간마다 통계 스냅샷을 끝낸다. 첫 줄이 `NOTHING`이면 그 줄만 보고하고 끝낸다(이 문서를 읽지 않는다). `ACTION`이면 마지막 줄 JSON의 항목만 아래 규칙으로 처리한다. SNS 목록은 사이트 워크플로가 매시 12분 `social/open/latest.json`에 저장한다(세션이 워크플로를 돌리고 기다리지 않는다). ET 3의 배수 시각 실행은 social-comments.yml(list)과 telegram.yml(텔레그램 채널 새 리포트, 11-11 운영자 지시)을 함께 실행 요청만 한다.

## AI 답글과 나눠 맡기(11-11)
사이트 comment-ai.yml(매시 15분)이 유튜브·Threads·페이스북 **첫 댓글 질문·의견**을 저가 모델로 답한다(리포트 본문 근거, 3장 규칙 자동 검사 통과분만 게시). 장부는 사이트 `social/llm/comments/state.json`: posted는 hourly.py가 건너뛰고, left는 `"ai":"AI 넘김: <사유>"`를 달아 넘긴다(사유를 보고 고쳐 답한다). 아직 시도 전인 2시간 안 질문은 hourly.py가 기다린다('AI 답글 대기 n'). 대댓글·종목 요청·AI 질문·스팸·투표·인스타는 지금처럼 이 문서대로. 키가 없거나 크레딧·예산이 없으면 장부가 ok가 아니므로 기존 방식 그대로다. 유튜브 하루 40개는 함께 쓰며 AI는 32개에서 멈춘다.

## 0. 운영자 지시(원문 요지)
- 하루 한도 안에서 모든 시청자 댓글에 답한다(감사·별 의미 없는 댓글 포함). 질문·의견은 리포트 숫자로 짧게 답해 반응과 리포트 방문을 늘린다(10-16·10-24·11-06).
- 답글 150자 이내(링크 제외) + 한 단어로 답할 수 있는 질문 하나로 끝낸다. 감사 답글은 질문 없이 1~2문장(10-16 승인).
- 요청 댓글은 접수 답글을 달고, 제작되면 같은 스레드에 완료 답글로 팔로우업(10-23).
- 사이트 요청 버튼·사이트 댓글도 요청 장부에 합친다(10-26). 리포트 페이지 댓글에도 대댓글(11-04).
- 오래된 댓글(7일 넘은 것)은 **23시 실행에서만** 남은 한도로 답한다(10-24 지시를 11-10 토큰 절약으로 하루 1회로 묶음).

## 1. UTM·조치
- 원고에는 리포트 맨 주소(https://drkimworld.com/r/<slug>/)만. 유튜브 `--kind top|followup|request`, SNS 답글 파일 항목 "kind".
- 홍보·스팸(외부 링크·리딩방·유료방·매매방·연락처·다른 서비스 홍보): 답하지 않고 조치. 유튜브 `python3 tools/yt_reply.py --moderate <댓글ID> --ban`, SNS 항목 `{"platform":..,"to":<댓글ID>,"action":"hide"|"delete"}`(Threads hide만, 인스타·페이스북 delete). 욕설·혐오는 `--moderate`(차단 없이)·hide. 단순 비판·반론은 조치하지 않는다. 조치는 한도 밖.
- AI인지 묻는 댓글(10-26 "삭제후 차단"): 다른 질문이 섞여도 답하지 않는다. 유튜브 `--moderate <댓글ID> --ban`(대댓글이면 comments API parentId로 ID 찾기), SNS hide/delete. 그 댓글에 단 우리 답글이 있으면 comments.delete로 함께 지운다. 보고에 '조치' 줄. 사이트는 숨김 도구가 없으니 '조치 필요' 한 줄.

## 2. 유튜브
- 같은 댓글에는 한 번만. 목록에 다시 뜬 스레드는 comments API로 우리 답글을 확인하고 중복하지 않는다. 우리 글·시청자끼리 대화는 답하지 않는다.
- 한도 ET 하루 40개. 넘치면 followup → 종목 요청 → 숫자 투표 → 질문·의견 → 감사 → 별 의미 없는 댓글 → 좋아요 순 → 최근 순.
- 영상↔리포트: youtube_id 일치 → 없으면 제목 종목명·#티커로 data/tickers.yaml → 그 종목 **최신** 리포트. 옛 영상도 같은 종목 최신 리포트가 있으면 질문·의견 답글에 '○월 ○일 업데이트' + 맨 주소. 리포트가 없으면 링크 없이 1문장 + 질문.
- 별 의미 없는 댓글에서 뜻을 짐작해 덧붙이지 않는다(정치인 이름만 있으면 '댓글 감사합니다'만). 재촉·'언제' 질문에는 "요청 장부에 올라 있고 만들면 이 댓글로 알려 드린다"(날짜·순서 약속 없이).
- 달기: `python3 tools/yt_reply.py --reply <threadId> --text-file <파일> --kind ...`, 여러 개면 python 스크립트 안에서 20~40초 간격(백그라운드). 실패한 답글은 다시 달지 않는다. 403이면 유튜브만 멈춘다.

## 2-1. 종목 요청(모든 채널)
- 티커 확인(tickers.yaml·리포트 머리말, 모르면 웹 검색 1회). 최신 리포트 data_as_of 7일 이내면(운영자 정정 11-11: 60일 아님) 숫자 1개 + 리포트 안내(kind request, 영상 있으면 https://youtu.be/<영상ID>).
- 없거나 7일 초과면 접수 답글(kind request): 종목 이름을 되짚고 "요청 장부에 올렸고, 영상과 리포트가 나오면 이 댓글에 링크로 알려 드리겠다" + 짧은 질문. 날짜·순서 약속, '후보로 올려 두겠습니다' 금지. 같은 업종 리포트 맨 주소 하나는 붙여도 된다.
- requests.md에 '대기'(같은 종목 행이 있으면 스레드 칸에 덧붙임). 스레드 칸: 유튜브 `threadId@videoId`, SNS `<채널>:<댓글ID>@<게시물ID>`, 사이트 `site:<id>@<b-티커>`. 결과 칸 '접수 답글 <ID>(MM-DD)', 궁금한 점이 있으면 '질문: <짧게>'. 제작 예약 칸 '예약 없음(요청 큐)'. 커밋·푸시. create_trigger 금지.
- 섞인 댓글은 리포트 있는 종목 링크로 답하고 없는 종목은 '요청 장부에 적었고 나오면 이 댓글로 알려 드린다' 한 문장. 비상장 등 자료 없음은 '보류' + "공개 자료가 쌓이면 다루겠다".
- 웹 요청(hourly.py의 site_request 항목): requests.md에 '대기'(출처 '웹 요청 n명', 같은 행이면 n만 갱신). 최근 7일 리포트를 낸 종목·완료 뒤 새 요청 없는 종목은 뺀다. 버튼 요청은 답글 대상이 없다.
- 23시 실행에서는 requests.md '완료'인데 결과 칸에 완료 답글이 없는 스레드에 완료 답글(새 영상 + 리포트 맨 주소, 인스타는 '프로필 링크의 무료 리포트')을 달고 ID를 적는다.

## 2-2. 대댓글
context를 끝까지 읽고 우리에게 한 말일 때만 답한다. 유튜브 `--kind followup`, 본문 맨 앞 @상대이름. 이미 한 말·숫자는 되풀이하지 않는다. 반박에는 리포트 사실로 담담하게, 범위 밖이면 "리포트 범위 밖이라 단정하기 어렵다".

## 2-3. 오래된 댓글(23시 실행만)
`python3 tools/yt_reply.py --list --days 3650`에서 7일보다 오래된 open. 순서: 대댓글 → 좋아요 순 → 질문·의견·요청 → 감사 → 별 의미 없는 댓글 → 최근 순. 첫머리 '늦은 답글이라 죄송합니다' 류(매번 다르게). 질문은 '○월 ○일 기준' 숫자 하나 + 맨 주소, 지금 가격·전망 금지, 매매 질문은 "개별 판단은 드리지 않습니다". 상폐·상장 여부는 확인한 공시 없이는 단정하지 않는다.

## 2-5. 사이트 댓글
질문·의견은 그 종목 최신 리포트 숫자 하나 + 기준 날짜 + 답이 있는 자리(리포트 N부 <표 이름>). 사이트 안이라 링크 없음(다른 종목 리포트만 맨 주소). '익명#xxxx'는 부르지 않는다. 게시: 사이트 저장소 `social/site_replies/<YYYYMMDD-HHMM>.json` {"replies":[{"parent":id,"slug":"b-<티커>","body":".."}]} main 푸시.

## 3. 답글 쓰기(모든 채널)
- 가독성(SKILL 0.2, 11-11): 숫자에는 비교 기준을 같은 문장에, 용어는 쓰면 한 구절로 풀고, 화살표·가운뎃점 나열 대신 짧은 문장.
- 리포트 파일의 확인된 숫자·날짜만, 기준 날짜를 붙인다. 150자 이내, 마크다운·이모지·해시태그 없음. 달기 전에 글자 수를 센다.
- 링크 붙인 질문 답글에는 '답은 리포트 N부 <표 이름>'(통합 인사이트 10-26).
- 투표 댓글: 정답을 말하지 않고 그 가설의 숫자 하나 + 리포트 안내.
- 링크는 질문·의견에만. 같은 스레드 같은 링크 반복 금지. 채널별 링크 답글 70% 이하(요청 제외). 문장 틀을 매번 바꾼다.
- 금지: 매수·매도 권유, 목표가, 수익 약속, 긴급성, 베팅 표현, '사기' 단정, 다른 시청자 비난, AI 언급, 운영자 개인정보·보유 종목, 개인 연락 약속, 정기 업데이트 약속. data_as_of 60일 초과면 '○월 ○일 기준', 현재 가격 금지.

## 4. SNS
- 인스타그램 댓글은 인스타팀 담당(skill/instagram/INSTAGRAM.md 7장, 11-11). hourly.py가 20시간 안 된 인스타 댓글은 넘기고, 그때까지 답이 없는 것만 여기서 처리한다(누락 방지).
- Threads는 투자(주식·코인) 게시물 댓글만 답한다(다른 주제는 개수만). 조치는 모든 게시물.
- 채널별: Threads 맨 주소·대댓글 @이름 / 인스타 링크 금지("프로필 링크 → 사이트에서 '<종목 이름>' 검색")·@이름 / 페이스북 맨 주소·"<이름>님,". 채널마다 하루 40개.
- 게시: 사이트 `social/replies/<YYYYMMDD-HHMM>.json` {"replies":[{"platform","to","text","kind"}]} main 푸시 → 워크플로가 게시하고 social/replies/done/에 결과. 실패 항목은 다시 올리지 않는다.

## 5. 보고
처리한 것만 짧은 표(채널, 종류, 댓글 앞 30자, 답글 앞 60자 또는 조치, 성공/실패) + hourly.py 첫 줄 요약. PushNotification은 실패(인증·권한·쿼터·워크플로 실패)일 때만.
